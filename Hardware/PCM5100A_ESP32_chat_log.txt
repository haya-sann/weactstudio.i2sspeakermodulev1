## 原因：複数の要因が重なっています

### 1. 最有力 — NS4150B Class-D アンプの熱的安定化

NS4150B はスイッチング式（Class-D）アンプです。内部の発振回路が**冷えた状態では動作点が不安定**で、スイッチング波形が乱れます。チップが動作温度（50〜70°C）に達するまでの時間がちょうど**5〜10分**に相当します。

### 2. CTRL/XSMT のタイミング問題（回路図から確認）

回路図を見ると：
- PCM5100A の **XSMT ピン（ソフトミュート）** と NS4150B の **CTRL ピン（シャットダウン）** が同じ `CTRL` 信号で制御されている
- `CTRL` は `/SD` ピン経由でマイコンから制御される

しかしサンプルコード（`i2s_test.ino`）では **`/SD` ピンを制御していない**。つまり、**DAC・アンプが初期化完了前から有効状態になっている**可能性が高く、起動時のノイズがそのままスピーカーへ出力されます。

### 3. PCM5100A の内部チャージポンプ（VNEG）の不安定

PCM5100A は内部で負電源（VNEG）をチャージポンプで生成します。その外付けコンデンサが C10・C13（2.2μF、0402サイズ）です。起動直後は VNEG が不安定で、DAC 出力に DC オフセットが乗り、アンプで増幅されてノイズになります。

---

## 対策

**ソフトウェア側で起動時ミュートを追加するのが最も効果的です：**

```cpp
#include "AudioTools.h"
#include "BluetoothA2DPSinkQueued.h"

#define SD_PIN 2  // /SD ピンに接続したGPIO番号（実際の配線に合わせて変更）

I2SStream i2s;
BluetoothA2DPSinkQueued a2dp_sink(i2s);

void setup() {
    // 起動時はアンプをミュート（CTRL = LOW）
    pinMode(SD_PIN, OUTPUT);
    digitalWrite(SD_PIN, LOW);

    auto cfg = i2s.defaultConfig();
    cfg.pin_bck = 14;
    cfg.pin_ws = 15;
    cfg.pin_data = 22;
    cfg.pin_mck = 0;
    i2s.begin(cfg);

    a2dp_sink.set_volume(0);  // 音量ゼロから開始
    a2dp_sink.start("MyMusic");

    // DACとアンプが安定するまで待つ
    delay(2000);

    // ミュート解除
    digitalWrite(SD_PIN, HIGH);

    // 徐々に音量を上げる
    for (int v = 0; v <= 20; v++) {
        a2dp_sink.set_volume(v);
        delay(50);
    }
}

void loop() {}
```

## まとめ

| 原因 | 寄与度 |
|------|--------|
| NS4150B の熱的安定化 | 大（10分という時間に一致） |
| 起動時ミュート制御なし | 大（回路図から確認） |
| PCM5100A VNEG 不安定 | 中（起動直後のノイズ） |

【Claude】
なるほど、それが根本原因です。

回路図を見ると、`/SD` は R8（10kΩ）で VDD33 にプルアップされています。つまり `/SD` が NC だと **CTRL は常に HIGH = アンプとDACは電源投入と同時に即座にアクティブ**になります。

```
VDD33
  │
 R8 (10kΩ)  ← /SD が NC なのでここからプルアップのみ
  │
 R9 (33Ω)
  │
CTRL ──→ PCM5100A XSMT（ミュート制御）
     └──→ NS4150B CTRL（シャットダウン制御）
```

つまり起動直後から：
- PCM5100A の VNEG チャージポンプが不安定な状態でも出力が有効
- NS4150B がそのノイズをそのまま増幅
- ミュートするタイミングが一切ない

**解決策は `/SD` を ESP32 の GPIO に接続することです。**

P1コネクタのピン3（`/SD`）を ESP32 の適当な GPIO（例：GPIO2）に配線して、先ほどのコードで起動時ミュートを制御するだけでかなり改善するはずです。

配線追加が難しければ、**電源投入後すぐに音を出さず数秒待ってから再生開始する**という運用で回避することもできますが、根本解決には `/SD` の配線が必要です。

「MC」は **MCLK（マスタークロック）** のことですね。

## MCLK の役割

PCM5100A DAC の内部 PLL（位相同期回路）に高精度なクロック基準を与えるための信号です。

通常、オーディオサンプルレートの **256倍または512倍の周波数**を入力します：

```
44.1kHz × 256 = 11.2896 MHz
48kHz   × 256 = 12.288 MHz
```

## 開放（NC）でも問題ない理由

PCM5100A には **Auto Clock Detection（自動クロック検出）** 機能があります。MCLK がなくても、**BCK（ビットクロック）と LRCK（左右チャンネルクロック）だけからサンプルレートを自動判別**して動作できます。

実際、ESP32 + PCM5100A の組み合わせでは MCLK を NC にするのはよくある構成です。

## MCLK を接続した場合との違い

| | MCLK なし（現在） | MCLK あり |
|---|---|---|
| 動作 | 問題なし | 問題なし |
| ジッター | やや多め | 少ない |
| 音質差 | Bluetooth 用途ではほぼ無視できる | わずかに有利 |

Bluetooth A2DP での音楽再生用途であれば、**MCLK は NC のままで全く問題ありません。**

## 仕組み

```
ACコンセント → USBハブ（セルフパワー）→ ESP32（電源 + データ）
                        ↓
                      Mac（Serial モニタ）
```

ハブ自身がACから電力を取るため、Mac の USB ポートの電流制限に縛られません。USB データはそのまま Mac に通るので Serial モニタも使えます。

## 選ぶときのポイント

- **セルフパワー（AC電源付き）** と明記されているもの
- 各ポートに **1A 以上**供給できるもの
- バスパワー（PCから給電）のみのハブは同じ問題が起きるので NG

Anker や BUFFALO などの有名ブランドのセルフパワーハブであれば十分です。現在お使いのハブは「バスパワー」タイプでしょうか？

## 解決策

**セルフパワーUSBハブに交換する**だけで解決します。

- データ通信（Serial モニタ）も同時に使える
- 追加の配線変更不要
- コード変更も不要（BOD無効化も不要）

Amazonで「セルフパワー USBハブ」で検索すると2,000〜4,000円程度で見つかります。Anker・BUFFALO・ELECOMあたりが信頼性高いです。

ハブが届いたらそのまま繋ぐだけで、以前に動いたコードがそのまま使えます。
